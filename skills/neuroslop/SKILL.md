# Нейрослоп в русском тексте

Нейрослоп — следы машинного текста: кальки с английского, хвостовые деепричастия, тире-паузы, шаблонная риторика. У Claude свой почерк, он описан первым в `reference.md`.

## Порядок работы

1. **Механический прогон.** `<base>` — каталог скилла (строка «Base directory for this skill» при загрузке):
   ```bash
   python3 <base>/scripts/detect.py <файл>     # или: pbpaste | python3 <base>/scripts/detect.py -
   ```
   Код (блоки и инлайн) скрипт пропускает. С pymorphy3 (`pipx install pymorphy3`, скрипт сам найдёт его venv) обороты ищутся по морфологии, без него — по суффиксам, ложных срабатываний больше. Скрипт только находит кандидатов, решаешь ты.
2. **Чтение глазами** по `reference.md`. Скрипт не видит порядок слов, смысловые кальки, ритм, пустоту и композицию. Это половина работы.
3. **Отсев.** Убери ложные срабатывания: тире по правилу, термин — определение в списке, одиночное причастие перед существительным, жаргон аудитории («под», «деплой», «MR»), канцелярит там, где он норма жанра.
4. **Замены.** На каждую находку — готовый текст, а не совет «перефразируйте».
5. **Самопроверка замен.** Сложи все свои «Стало» и переписанный текст в файл во временном каталоге и прогони `detect.py` ещё раз. Перечитай по разделу 1 `reference.md`. Каждое срабатывание в твоём тексте — твоя ошибка, исправь до выдачи. Чаще всего в замену просачиваются «не X, а Y», «Дело не в…», тире-пауза и предложение помощи в конце. Затем сверь словарь: каждое новое существительное или глагол в «Стало», которого нет в «Было», проверь grep'ом по документу. Если для того же понятия там другое слово, замена подменяет термин — верни слово документа.

## Правила замен

- **Факты неприкосновенны:** числа, имена, команды, код, термины, условия и оговорки («обычно», «если», «примерно») переносятся как есть.
- **Термины в «Стало» — из словаря текста.** Новое слово для технического действия или объекта, которого не было в «Было», сначала ищи grep'ом по документу и соседним страницам. Есть своя основа — бери её: «рендерит» в тексте → «отрендерил», не «отрисовал». Обрусить термин — такая же ошибка, как калька (`reference.md`, конец раздела 5).
- Не выдумывай конкретику. Где тексту не хватает цифры или примера, так и напиши: «нужен пример от автора».
- Короче — не всегда лучше. Если от фразы ничего не осталось, удали её целиком.
- Сохраняй голос автора и жанр: в техдоке не пиши разговорно, в посте не пиши как в ГОСТе.

## Формат ответа

Ответ состоит ровно из этих частей, по порядку:

1. **Диагноз** — 1–3 строки: насколько текст заслопован (чисто / пятна / сплошь) и две-три главные болезни с цифрами из статистики скрипта.
2. **Правки** — таблица, по порядку текста:

   | Строка | Было | Стало | Признак |
   |---|---|---|---|
   | 13 | Честно говоря, это довольно типичная ловушка. | ∅ | ложная доверительность, хедж |
   | 15 | …в базу, используя паттерн write-through. Это даёт нам гарантию того, что кэш… | …в базу. Тогда кэш… | хвостовое деепричастие, «Это даёт» |

   «Было» — точная цитата, «Стало» — готовый текст, ∅ — удалить.
3. **Общее** — только если есть правки, которые не сводятся к строке: ритм, композиция, списки вместо абзацев, где не хватает конкретики.
4. **Переписанный текст** — если текст до ~300 слов или пользователь попросил переписать. Если пользователь просил поправить файл, примени правки через Edit вместо этого пункта.

5. **Самопроверка** — одна строка: `Самопроверка: detect.py по «Стало» и переписанному тексту — N срабатываний.` Если N > 0 по разделам риторика, подводка, концовка, калька, обрусение или тире-драма, ответ не готов: исправь и прогони снова. Оставшиеся срабатывания (термин, жаргон) перечисли через запятую с причиной.

Строка самопроверки — последняя строка ответа. Без итогов, вопросов и предложений помочь ещё.
